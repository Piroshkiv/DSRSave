# DS3 — локализация блока костров / event-флагов (через watcher)

Результат реверса блока «разблокировать все костры» в расшифрованном слоте DS3.
Данные: watcher-снимки `lock / lock2 / unlock / unlock2 / unlock3 / unlock4`
(`…/DarkSoulsIII/011000013017fff9/watcher/*/*.bin`, слот = 786436 байт).

## TL;DR

- **Абсолютные оффсеты в слоте бесполезны.** Между сейвами layout уезжает на тысячи
  байт (в эксп.1 инвентарь вырос → сдвиг `+0x11E0`). Всё держится на якорях.
- `CHARACTER_PATTERN` (первое глобальное совпадение, как в текущем DS3-коде) **не годится**
  как якорь для костров: его позиция плавает (`0xFA5C / 0x10520 / 0x11700`), а между ним
  и блоком лежат переменные данные (инвентарь + ещё ~0xA0).
- **Рабочий механизм — как в DS1** (`Character.findPattern1`): поиск паттерна `FF·4 00·4 FF·4 00·4`
  в окне + выбор конкретного вхождения. Локальный якорь даёт блок костров **байт-в-байт**.

## Механизм поиска блока костров (верифицирован)

```
P16  = FF FF FF FF 00 00 00 00 FF FF FF FF 00 00 00 00   // == DS1 Pattern1

1. invStart = findInventoryStart(slot)        // уже есть в offsetPatterns.ts (скан GA-таблицы)
2. est      = invStart + 0x12B1F              // грубая оценка старта блока
3. anchor A = ПОСЛЕДНЕЕ вхождение P16 в окне [est-0x1500, est+0x200]
4. rec0     = A + 0xB5D                        // старт блока костров/флагов
```

Проверка `find_rec0` против независимого детектора структуры:

| файл | mechanism | truth | совпало |
|------|-----------|-------|---------|
| unlock  | `0x243FB` | `0x243FB` | ✅ |
| unlock2 | `0x2321B` | `0x2321B` | ✅ |
| unlock3 | `0x2321B` | `0x2321B` | ✅ |
| unlock4 | `0x227F7` | `0x227F7` | ✅ |
| lock / lock2 | `0x2321B` | — (залочено, маркеров нет) | якорь резолвится корректно |
| **unlock5** (др. персонаж `011000014bb08ffd`) | `0x21FEB` | `0x21FEB` | ✅ |

**Кросс-персонажная проверка (unlock5).** Другой сейв-фолдер, другой персонаж
(`invStart=0xF314`, `rec0=0x21FEB` — иная абсолютная позиция). Механизм резолвит блок
точно, и **все 8 записей костров совпали с эталонной картой «unlock all» байт-в-байт** —
механизм переносим между персонажами, не подогнан под один сейв.

Почему именно так: `rec0 − A` = `0xB5D` **константа для всех 4 unlock, включая выброс unlock4**
(где inventory-якорь ошибается на `+0xA0`). P16-локальный якорь точнее inventory-якоря.

## Структура блока

- Блок состоит из **записей по `0x500` байт**: `rec_i @ rec0 + i*0x500`.
- Флаги костров в записи — два 16-битных слова (LE):
  - `rec + 0x000` (u16)
  - `rec + 0x40E` (u16)
  - (в rec0 дополнительно бит на `+0x007`)

Аналог DS1, где костры — биты в `base+0x6B/0x6C/0x6D`; в DS3 областей больше, поэтому
они разложены по записям с шагом `0x500`.

## Карта «unlock all» (чистый дифф lock2 → unlock2, выровнено по механизму)

```
rec 0  (rec0+0x0000):  +0x0=B0 +0x1=03  +0x7=80   +0x40E=40 +0x40F=EC
rec 1  (rec0+0x0500):  +0x0=80 +0x1=03            +0x40F=E0
rec 2  (rec0+0x0A00):  +0x0=E0 +0x1=03            +0x40F=F8
rec 4  (rec0+0x1400):  +0x0=C0 +0x1=03            +0x40F=F0
rec 6  (rec0+0x1E00):  +0x0=FE +0x1=02  +0x40E=80 +0x40F=BF
rec 8  (rec0+0x2800):           +0x1=03           +0x40F=C0
rec 9  (rec0+0x2D00):  +0x0=80 +0x1=03            +0x40F=F0
rec12  (rec0+0x3C00):  +0x0=FE +0x1=03
```

Все изменения — `00 → значение` (выставление бит). 25 изменённых байт, 8 записей.
Записи 3/5/7/10/11 не менялись между этим lock2 и unlock2 (уже в том же состоянии
либо не костровые).

## Кросс-валидация

Два независимых прогона lock→unlock дали **одинаковые оффсеты (относительно якоря) и
одинаковые значения** байт-в-байт:

| смещение (от паттерна, эксп.) | эксп.1 unlock | эксп.2 unlock2 |
|---|---|---|
| rec0 `+0x0/+0x1` | `B0 03` | `B0 03` |
| rec0 `+0x40E/+0x40F` | `40 EC` | `40 EC` |
| rec1 `+0x0` | `80` | `80` |
| rec2 `+0x0` | `E0` | `E0` |

## Проверенные паттерны DS3 (`src/apps/ds3/lib/offsetPatterns.ts`)

| паттерн | позиция | пригодность как якорь костров |
|---|---|---|
| `CHARACTER_PATTERN` (32B `FF·4 00·12` ×2), первое глоб. совпадение | `0xFA5C / 0x10520 / 0x11700` (плавает) | ❌ далеко, между ним и блоком переменные данные |
| GA-table (`0x70`, фикс.) | `0x70` | ❌ слишком далеко |
| `findInventoryStart` (скан GA) | варьируется | ⚠️ только грубо: `rec0−invStart = 0x12B1F` (±0xA0 на unlock4) |
| **P16 `FF·4 00·4 FF·4 00·4` (DS1 Pattern1), последнее в окне** | `rec0 − 0xB5D` | ✅ **точно на всех снимках** |

## Замечания по данным watcher

- Хвост слота `> ~0x77000` — устаревшее содержимое буфера игры (мусор), в диффах не участвует.
- Внутри одного события ранние снимки (`_001..003`) стабильны, поздние часто «взрываются»
  на 250k+ байт из-за перезаписи хвоста — для диффа брать стабильных представителей.
- Залоченное состояние: флаги = 0, поэтому детектор структуры по маркеру `0x03` не срабатывает —
  для locked-файлов позицию блока даёт только якорный механизм (P16), не детектор.
