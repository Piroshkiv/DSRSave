# DS3 Gesture Sweeper

Ищет, **где в сейве DS3 лежат флаги разблокировки жестов**, чтобы сделать в
редакторе вкладку Gestures. Полный аналог `ds1-gesture-sweeper`, но для DS3.

Приём тот же: правим значения **в памяти процесса** (как это делает Cheat Engine
по `DS3_TGA_v3.4.0.CT`, скрипт *Unlock All Gestures*), заставляем игру сохраниться
через **ESC ×2**, дампим расшифрованный слот и побитово сравниваем дампы.

## Откуда взяты офсеты памяти

Из `DS3_TGA_v3.4.0.CT`:

```
GameDataMan = AOB `48 8B 05 ?? ?? ?? ?? 48 85 C0 ?? ?? 48 8B 40 ?? C3`, RIP-relative (+7)
таблица     = [[[GameDataMan]+0x10]+0x7B8]+0x10
запись i    = таблица + 4*i, формат [u16 value][u16 index]
```

```
Locked   value = (i+1)*2
Unlocked value = (i+1)*2 + 1     // бит 0 = «разблокирован»
```

Ровно та же структура, что в DS1 — только цепочка другая и жестов 41 вместо 15.

### Список жестов

Индексы `0x00`–`0x20` — из скрипта *Unlock All Gestures*. Индекс `0x21`
(Unmannered Bow) в том скрипте закомментирован, но это рабочий жест — имя взято
из дропдаунов *Equipped Gestures*.

**Записи `0x22`–`0x28` — сломанные.** `Lord of Cinder` — незаконченный жест:
должен был ставить персонажа в идл-позу Soul of Cinder, но играет
placeholder-анимацию броска кукри. `FDP_MenuText(301140…301145)` — пустые
заглушки. Флаг у них ставится и игра его сохраняет, но в игровом меню они
выглядят сломанными (проверено в игре). Редактор их **не показывает и гасит**
при «unlock all».

`Unmannered Bow` (`0x21`) — тоже вырезанный контент и тоже добывается только
через CE, но анимация у него целая, жест рабочий, и подтверждённых банов за него
не нашлось. Оставлен. Помни при этом, что DS3 в принципе умеет выдавать soft ban
за аномальные данные в сейве.

В памяти и в сейве лежат **все 41 записи**, включая вырезанные, и прогон идёт по
всем 41 — иначе не проверить структуру таблицы.

## Требования

```bash
pip install -r requirements.txt      # pymem, pycryptodome
```

Игра запущена, персонаж **загружен в мир** (не в главном меню), окно в
window/borderless режиме.

## Использование

```bash
python memory.py                      # адреса + текущее состояние жестов (без записи)
python sl2.py <DS30000.sl2>           # слоты, найденные таблицы и дельты до якорей
python main.py --list                 # слоты сейва покороче

python main.py --slot 4 --out ./out   # полный прогон
python main.py --slot 4 --only 0,32,33,34
python main.py --analyse-only --out ./out

python anchors.py                     # подбор якоря по всем профилям
```

### Что делает полный прогон

1. Все жесты → **Locked**, сейв, дамп → `baseline_all_locked.bin`
2. Для каждого `i`: всё Locked **кроме** `i`, сейв, дамп → `gNN_<slug>.bin`
3. Все → **Unlocked**, сейв, дамп → `final_all_unlocked.bin`
4. Возвращает исходное состояние жестов и **проверяет по файлу**, что оно
   действительно вернулось (отключается `--no-restore`)
5. `diff.py` строит `report.md`

Перед началом кладёт копию `.sl2` в `--out` (`DS30000.backup.<ts>.sl2`).

### Важно во время прогона

- ESC уходит **в активное окно** — фокус программно не крадём (игра его не
  принимает). В начале идёт отсчёт: разверни игру и дальше не трогай
  клавиатуру/мышь до конца.
- 41 жест = **43 сейва** по ~9 МБ, это ~7 минут. Гоняй на тестовом персонаже.
- В отличие от DS1, слот здесь задаётся явно (`--slot`): DS3 при сейве трогает
  больше одного энтри, так что автодетект по «какой слот изменился» ненадёжен.
  Скрипт всё же предупредит, если указанный слот после сейва не изменился.

## Про якорь — чем DS3 отличается от DS1

В DS1 таблица жестов нашлась на **фиксированном абсолютном офсете** `0x1E4A8`
(во всех 26 персонажах), а вот pattern1-относительная дельта плавала.

В DS3 всё наоборот: слот содержит инвентарь переменной длины, и абсолютные
офсеты едут вместе с ним. Поэтому `anchors.py` меряет найденную таблицу от всех
якорей, которые уже используются в редакторе:

| якорь | откуда |
|---|---|
| `character_pattern` | `CHARACTER_PATTERN` — якорь статов/имени/уровня |
| `inventory_start` | скан GA-таблицы (`findInventoryStart`) |
| `bonfire_block` | оконный поиск `BONFIRE_PATTERN` + `BONFIRE_ANCHOR_TO_BLOCK` |
| `steamid` | указатель на `0x58` + сигнатура `01 00 10 01` |
| `absolute` | офсет от начала слота |

Годный якорь — тот, у которого дельта одинакова во **всех** персонажах всех
профилей. Даже когда якорь найден, поиск по сигнатуре записей остаётся как
проверка и как фолбэк.

## Как читать `report.md`

- **Биты-кандидаты** — изменились ровно в одном дампе → флаг этого жеста.
- **Сверка с таблицей** — легли ли все биты ровно в `таблица + index*4`, бит 0.
- **Дельты от якорей** — для выбора якоря (окончательный вывод даёт `anchors.py`).
- **Шум** — биты, изменившиеся во всех дампах (таймер, позиция и т.п.).
- **Контроль** — дифф all-locked → all-unlocked.

## Результат прогона (2026-09-12, слот 4 профиля 011000013017fff9)

43/43 сейва прошли, карта 1:1 — **все 41 жест легли ровно в `таблица + index*4`, бит 0**.
Структура записи `[u16 value][u16 index]` подтверждена, как и в DS1.

```
таблица+0x00: 02 00 00 00  04 00 01 00  06 00 02 00  08 00 03 00   <- все locked
таблица+0x00: 03 00 00 00  05 00 01 00  07 00 02 00  09 00 03 00   <- все unlocked
```

### Якорь: не подошёл ни один существующий

Проверено на **14 персонажах из 4 сейвов** (`anchors.py`):

| якорь | разброс дельты | годен |
|---|---|---|
| `character_pattern` | +0x114A0 … +0x11790 (0x2F0) | нет |
| `inventory_start` | +0x112C4 … +0x115B4 (0x2F0) | нет |
| `bonfire_block` | −0x185B … −0x18E3 (**0x88**) | как грубая оценка |
| `steamid` | гуляет, а у части слотов ID вообще нет | нет |
| `absolute` | гуляет | нет |

Мало того, офсет **едет даже между двумя сейвами одного персонажа**
(0x21F98 → 0x219E8 за прогон). Поэтому в редакторе сделано как с самим блоком
костров: грубая оценка `findBonfireBlock() + GESTURE_COARSE_FROM_BONFIRE`
(−0x1863), поиск сигнатуры в окне ±0x800 вокруг неё, полный скан как фолбэк,
и проверка структуры всех 41 записи как приёмка.

Проверка алгоритма: **63 попадания из 63** (43 дампа прогона + 6 слотов бэкапа
+ 14 персонажей четырёх сейвов), окно срабатывало всегда — до полного скана
дело ни разу не дошло.

### Копии таблицы в хвосте слота

В слоте бывает **второе** совпадение сигнатуры — копия таблицы в runtime-хвосте
(`0x819F8` / `0x9B528` при размере слота `0xC0010`). Она плавает между сейвами и
в диффе выглядит как «изменения», хотя данные там неактуальные. Правило: берём
**первое (самое младшее)** совпадение — проверено на всех 43 дампах.

## Файлы

| Файл | Назначение |
|---|---|
| `constants.py` | офсеты памяти из CT, имена/слаги жестов, константы `.sl2` |
| `memory.py` | резолв GameDataMan (AOB) + чтение/запись записей жестов |
| `input_save.py` | ESC ×2 через SendInput (scancode) + ожидание записи сейва |
| `sl2.py` | BND4 + AES, якоря слота, поиск таблицы по сигнатуре |
| `anchors.py` | подбор якоря по всем профилям |
| `diff.py` | побитовый анализ дампов → `report.md` |
| `main.py` | драйвер прогона |
