# DS1 Appearance Sweeper

Внешность DSR: **память ↔ сейв ↔ `.dsrchr`**. Нужен, чтобы импорт/экспорт
внешности в редакторе был совместим с
[DSAppearancePresetTool](https://github.com/BobDoleOwndU/DSAppearancePresetTool)
(BobDoleOwndU), и чтобы находить в сейве любые другие поля PlayerGameData.

Тот же приём, что у `ds1-gesture-sweeper`: правим значение в памяти игры,
заставляем её сохраниться (ESC ×2), диффим расшифрованный слот. Плюс режимы
**без записи** — сверка памяти с сейвом и слежение за изменениями.

## Откуда офсеты памяти

Из исходников мода (`Remastered.cs`) и `1FRDarkSoulsRemastered.CT`:

```
BaseB = AOB `48 8B 05 ?? ?? ?? ?? 45 33 ED 48 8B F1 48 85 C0`, RIP-relative (+7)
PGD   = [[BaseB]+0x10]
```

| поле | PGD | слот | тип | в `.dsrchr` |
|---|---|---|---|---|
| sex | `0x0CA` | `0x012A` | u8 | байт 0 |
| physique | `0x0CF` | `0x012F` | u8 | байт 1 |
| face_type (индекс меню) | `0x114` | `0x0174` | u8 | — |
| hair_index (индекс меню) | `0x115` | `0x0175` | u8 | — |
| color_index (индекс меню) | `0x116` | `0x0176` | u8 | — |
| **hair_id** | `0x354` | **`0x0344`** | i32 | байты 2..5 |
| hair_color | `0x4C0` | `0xE414` | 4×f32 | байты 6..17 (RGB) |
| eye_color | `0x4D0` | `0xE424` | 4×f32 | байты 18..29 (RGB) |
| face_data | `0x4E0` | `0xE434` | 50 байт | байты 30..79 |
| skin_color | `0x512` | `0xE466` | 50 байт | байты 80..129 |

`.dsrchr` — 130 байт без заголовка, поля подряд; цвета копируются сырыми
байтами, альфа в файл не попадает.

## Что было не так с волосами (2026-09-19)

Причёска, которую рисует игра, — это **надетая деталь** в блоке экипировки
(`PGD+0x354` → слот `0x344`, рядом с ID брони):
женские `3000 + 100·i`, мужские `1000 + 100·i`, `i = 0..9`.

Редактор вместо этого писал int32 в `0x175`. Это `PGD+0x115` — **индекс в
списке меню создания** (байт), игра по нему ничего не рисует. К тому же int32
затирал три соседних байта: индекс цвета (`0x176`), CurseLv (`0x177`),
InvadeType (`0x178`). Формула перевода `.dsrchr` → «индекс» тоже была
перевёрнута (жен. 1200+, муж. 3000+ вместо 3000+ / 1000+).

Как нашлось: пресет `Lyra.dsrchr` (sex 0, hair 3200) был импортирован в
`goober` редактором — в `0x175/0x176` лежало `09 05` (то есть `0x509`,
«индекс 20» зажат до 9), а в `0x344` остался старый `1100`. `--locate` показал,
что блок экипировки PGD лежит в слоте со сдвигом `-0x10`, и `PGD+0x354` = `0x344`.
По 29 персонажам из 7 файлов сейва: у всех `0x344` — из этого списка ID, и у
всех, кроме двух, индекс меню `0x175` с ним согласуется (`sex 0, idx 3 → 3300`,
`sex 1, idx 7 → 1700`, `sex 1, idx 9 → 1900`). Исключения — `goober` (испорчен
старым импортом) и мужской персонаж с женской причёской `3400`: игре
всё равно, какого «пола» деталь, поэтому редактор такой ID сохраняет как есть.

Остальные поля (пол, телосложение, цвета, лицо, кожа) у редактора были
правильные — `--read` даёт 10 из 10.

## Карта PGD → слот

`--locate` (окно 16 байт, только однозначные совпадения):

```
PGD 0x010..0x1C7  -> слот +0x60      статы, имя, пол, телосложение, индексы меню
PGD 0x2A8..0x2E3  -> слот +0x4
PGD 0x31C..0x373  -> слот -0x10      экипировка, hair_id
PGD 0x4C4..0x54B  -> слот +0xDF54    цвета, лицо, кожа
PGD 0x680..0x7FF  -> слот -0x310
```

Сейв хранит PGD кусками — абсолютный офсет поля в памяти ничего не говорит о
его офсете в слоте, пока не найден кусок, в который оно попадает.

## Требования

```bash
pip install -r requirements.txt      # pymem, pycryptodome
```

Игра запущена, персонаж **загружен в мир**, окно в window/borderless.

## Использование

Только чтение (игру не трогают):

```bash
python memory.py                          # адреса + поля внешности из памяти
python main.py --list                     # слоты сейва
python main.py --read                     # поля: память vs сейв, == / !=
python main.py --locate                   # какие куски PGD где лежат в слоте
python main.py --check-dsrchr             # .dsrchr из памяти (мод) vs из сейва (редактор)
python main.py --export-dsrchr me.dsrchr  # экспорт ровно как у мода
python main.py --save-dsrchr me.dsrchr --slot 0   # экспорт как у редактора (игра не нужна)
python dsrchr.py a.dsrchr [b.dsrchr]      # показать / сравнить пресеты по полям

python main.py --watch                    # слежение, Ctrl+C — выход
python main.py --watch --seconds 120 --dump ./watch
python main.py --watch --region-start 0x4C0 --region-size 0x90 --with-settings
python main.py --diff ./watch/save001_slot0.bin ./watch/save002_slot0.bin
```

`--watch` опрашивает PGD каждые 50 мс и печатает каждый изменившийся байт
(с именем поля и офсетом в слоте, если он известен по карте), а когда игра
пишет `.sl2` — дифф всех слотов персонажей относительно прошлого сейва.
Меняешь что-то в игре → видишь, какой байт памяти шевельнулся → жмёшь ESC ×2 →
видишь, куда он лёг в сейве. `--dump` складывает слоты и PGD каждого сейва
для последующего `--diff`.

С записью в игру (гоняй на тестовом персонаже, бэкап `.sl2` кладётся в `--out`):

```bash
python main.py --import-dsrchr me.dsrchr          # импорт ровно как у мода
python main.py --probe hair_id --value 3200       # поле -> сейв -> дифф -> откат
python main.py --probe eye_color --value 1,0,0
python main.py --sweep                            # маркеры во все поля .dsrchr
```

`--probe`/`--sweep`: сейв «до» → запись в память → сейв → дифф слота →
проверка, что значение легло ровно по офсету редактора, → откат → сейв.
Результат в `out/result.json`, дампы `before.bin` / `after.bin`.

`hair_id` пишется только из списка известных ID (`--force`, чтобы снять
ограничение): несуществующая модель может уронить игру, как это было с
ID-полями в DS3.

## Файлы

| Файл | Назначение |
|---|---|
| `constants.py` | цепочка памяти, таблица полей (PGD ↔ слот), раскладка `.dsrchr`, константы `.sl2` |
| `memory.py` | резолв BaseB/PGD, чтение/запись PGD и полей |
| `dsrchr.py` | формат `.dsrchr`: из памяти (как мод), из слота (как редактор), сравнение |
| `sl2.py` | расшифровка слотов (копия из `ds1-gesture-sweeper`) |
| `input_save.py` | ESC ×2 + ожидание записи сейва (копия из `ds1-gesture-sweeper`) |
| `main.py` | все режимы |
